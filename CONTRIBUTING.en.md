# Contributing

Issues and pull requests are welcome. Please read this page first, because the project has a few conventions that differ from a typical code repository. Most design documents and code comments are in Chinese. Issues and PRs may be written in English or Chinese.

## Setup

Node.js 22.12 or later (`.nvmrc` and the Dockerfile use Node 24).

```bash
cd game
npm install
npm run dev          # http://localhost:5173
npm test             # vitest
npm run typecheck
npm run build
```

Before opening a PR, make sure `npm run typecheck`, `npm test`, `npm run board` and `npm run build` pass. CI runs the same checks. The full command list is in [`game/README.md`](game/README.md).

## Project conventions

**Where rules and numbers live.**
- Rules follow `docs/GDD.md` and numbers follow `data/*.json`. When they disagree, the JSON wins and the document must be corrected to match.
- `game/` only reads `docs/` and `data/`. Do not edit them while implementing code. A rule or number change belongs in its own PR with a stated reason.
- Rule interpretations, simplifications and contradictions found in the documents go in [`game/NOTES.md`](game/NOTES.md).
- Numbers live in `data/config.json` and are read through `this.cfg.x.y`. Do not hardcode literals.

**Architecture.**
- `game/src/core/` is the plain-TypeScript rules engine. It **must not import Phaser**.
- All randomness goes through `core/rng.ts`. Never use `Math.random()`, or games can no longer be replayed (a determinism test covers this).
- A new kind of player decision needs both a new `kind` and its type in `ChoiceValueMap`.
- The checklist for adding spells, tile types or heroes is under "如何扩展" in [`game/README.md`](game/README.md).

**Balance changes.** After changing rules or numbers, run `npm run sim -- --games 500 --seed 1`, compare the result with the GDD §12 targets, and paste it in the PR description.

**Theme and language.**
- Use only generic "mortal cultivation" fantasy elements. Do not use names, places or sects from any specific novel.
- Player-facing text, battle logs and documents are in Chinese.
- Do not commit `dist/`, `node_modules/` or `game/screenshots/` (the last is generated by `npm run shots` and is ignored).

## Pull requests

- One PR does one thing. State the motivation and how you verified it.
- A bug fix should come with a test that reproduces it.
- Contributions are released under the [MIT License](LICENSE).

## Reporting problems

- Use the issue templates for bugs and suggestions.
- A game record (the JSON downloaded with the S key during a game) lets us replay a game exactly. Please attach one for rule or AI problems.
- For security issues see [SECURITY.md](SECURITY.md).
